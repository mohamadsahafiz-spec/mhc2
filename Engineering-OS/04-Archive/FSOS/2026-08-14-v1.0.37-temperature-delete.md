# FSOS v1.0.37 — Temperature Inspection Delete Fix

**Date:** 14 Aug 2026  
**Version:** v1.0.37  
**Type:** Bugfix

## Problem

A saved Temperature Inspection record could be reopened, but the Delete action did not successfully remove the record from authoritative persistence.

## Root cause

`handleDeleteSavedRecord` lacked a direct authoritative `StorageService.saveMachines` dispatch.

The UI action therefore did not complete the required authoritative persistence path.

## Fix

The deletion path was corrected so the Temperature Inspection deletion reaches authoritative storage and the associated TempRawStore telemetry is purged.

## Verification

Verified:
- record deletes from the Temperature Inspection workflow;
- TempRawStore telemetry is purged;
- authoritative storage is updated;
- record remains deleted after reload;
- Temperature graphs remain functional;
- downsampling remains functional;
- unselected records remain intact;
- all 8 tests pass.

## Protected areas

No Temperature Engine redesign was required.

No change was made to:
- Customer identity architecture;
- Machine Passport;
- Recommended Parts identity;
- unrelated MHC engineering calculations.

## Engineering lesson

Destructive UI actions must be verified through the full persistence lifecycle, not only by observing immediate UI state.

For authoritative records, regression verification must include:
`action → authoritative persistence → reload → absence/persistence confirmation`.

This lesson is reusable for future CRUD operations.
