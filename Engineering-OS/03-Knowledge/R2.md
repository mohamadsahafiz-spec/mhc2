# Cloudflare R2

## Technology Status

- **Current Usage:** Not activated for FSOS
- **FSOS Need:** Candidate solution for durable image/evidence storage
- **Adoption:** Deferred pending cost decision
- **Learning Priority:** High

## Purpose

R2 is object storage for binary assets such as images, reports, and backups. It should not be used as a relational database.

## FSOS Current Situation

FSOS currently stores image payloads in browser IndexedDB and synchronizes only image pointers through D1. This means images do not automatically survive a new device/browser.

R2 would solve the durability/cross-device problem, but activating it creates an ongoing usage-based storage dependency. It is therefore not activated until explicitly approved.

## Free-First Gate

Before activating R2 or another paid-capable object store, document:

- Free allowance
- Storage price
- Operation/read/write pricing
- Growth behaviour
- Retention/lifecycle behaviour
- Expected FSOS workload
- Migration/export path
- Maximum practical upload size

Founder approval is required before activation.

## Security

If R2 is eventually adopted for FSOS evidence:

- Prefer a private bucket.
- Keep R2 credentials out of the browser.
- Access objects through an appropriately secured Worker/API layer unless another access model is explicitly approved.
- Validate object identifiers and upload types/sizes.

## Current Decision

Do not activate R2 merely to remove a red status indicator. First evaluate genuinely free/no-billing alternatives. If R2 becomes the justified choice, activate it deliberately and design cost controls from the beginning.
