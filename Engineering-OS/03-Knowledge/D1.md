# Cloudflare D1

## Technology Status

- **Current Usage:** Active
- **FSOS Production:** Yes
- **Adoption:** Production
- **Learning Priority:** High

## Purpose

D1 is the relational persistence layer for FSOS operational data.

## FSOS Responsibilities

D1 stores authoritative structured records. The Worker is responsible for API/business logic; D1 is responsible for durable relational persistence.

## Production Rules

- Schema changes are version-controlled migrations.
- Production migration state must be verified before relying on a schema change.
- Application code must not silently fall back to volatile in-memory persistence.
- Persistence failures must surface as explicit failures rather than false success.
- Indexes should be justified by observed query patterns.

## Synchronization Rule

For FSOS record data:

**Client → Worker → D1**

D1 is the authoritative server-side source of truth.

## Common Mistakes

- Treating Worker memory as durable storage.
- Swallowing database errors.
- Assuming local schema equals production schema.
- Applying production migrations without verification.
